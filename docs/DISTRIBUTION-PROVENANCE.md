# Distribution provenance

This ledger records why each non-code asset or external compatibility artifact
is included in the public candidate. It is a release policy and evidence log,
not legal advice.

Reviewed: 2026-08-28.

## Project source and branding

- Keyword Pro source code, logos, icons, and application SVG artwork are
  project assets distributed under Apache License 2.0.
- The eight application screenshots were captured from the actual local
  interface at 1280 by 720 using the deterministic synthetic demo generated by
  `scripts/lib/synthetic-demo.ts`. The report records 27 keywords, 19 synthetic
  source records, zero provider calls, and zero provider cost.
- `scripts/seed-synthetic-demo.ts` refuses to run without an explicit
  confirmation flag and a local database whose name begins with
  `keyword_pro_demo_screenshots`. This keeps release capture work away from a
  normal installation database.
- `public/images/screenshots/manifest.json` records the reviewed image set,
  dimensions, and SHA-256 digests. `pnpm --ignore-workspace
  verify:screenshot-provenance` rejects missing, changed, extra, resized, or
  metadata-bearing PNG files.
- Screenshots containing captured provider results are not eligible for the
  public candidate.
- PNG and SVG release assets must pass metadata and embedded-text scans before
  archive approval.

## Fonts

The bundled Noto Sans, Noto Sans Mono, and Noto Serif files remain under SIL
Open Font License 1.1. Their copyright notice and complete license are kept in
`src/assets/fonts/OFL.txt` and summarized in `THIRD_PARTY_NOTICES.md`.

## Provider compatibility artifacts

- `scripts/fixtures/dataforseo` contains only deterministic synthetic values
  generated by `scripts/generate-synthetic-fixtures.ts`.
- Reserved `.invalid` domains, zero costs, and synthetic identifiers prevent a
  fixture from being mistaken for a captured account response.
- `pnpm --ignore-workspace verify:fixture-provenance` fails if committed bytes
  differ from the repository-owned generator.
- Endpoint names, request fields, response field names, and targeting codes are
  retained only as interoperability facts needed to call and interpret the
  service. Source URLs are recorded in generated files where available.

## Why captured responses are excluded

The DataForSEO Terms of Service, updated 12 June 2026, define material developed
through the API as service Content and place restrictions on some SERP data
uses. The terms page did not provide an explicit public redistribution license
for captured API payloads. That absence is not a legal conclusion that every
redistribution is forbidden. It is enough uncertainty for this project to use a
fail-closed policy and exclude captured responses from distributable source.

Primary source:
<https://dataforseo.com/terms-of-service>

## Release gate

The public candidate is blocked if any of the following is true:

- a committed test fixture cannot be reproduced by the synthetic generator;
- an application screenshot differs from the reviewed screenshot manifest;
- a screenshot contains unreviewed live provider data or personal information;
- an asset lacks a project-ownership record or compatible third-party license;
- a source archive contains credentials, local database content, logs, exports,
  build output, or private agent state.
