migrates, seeds, builds, starts, and renders from a clean one-commit projection.

history contains seven commits with non-placeholder author metadata. The

## Verified evidence

### Clean install and data lifecycle

- `pnpm install --frozen-lockfile --ignore-workspace` installed the locked
  dependency graph in a clean one-commit candidate.
- `pnpm --ignore-workspace db:migrate` created a fresh canonical schema. A
  second run reported the schema current and made no migration change.
- `pnpm --ignore-workspace seed` created the local user.
- `pnpm --ignore-workspace legacy:inventory` returned counts only. The release
  owner's inspected database contained zero saved sessions, opportunities,
  credential rows, and configured legacy values, so no private export or
  deletion was required.

## Owner gates

1. Choose the clean-history cutover strategy. Recommended: preserve the current
   private repository as an archive, then place the verified one-commit
   projection at the public `keywordpro` URL. Replacing the current history in
   place is destructive and requires a separate, explicit approval and backup.
2. Decide whether to spend approximately the displayed guided-report estimate
   for one real provider run. If approved, record actual cost, source count,
   saved reopen, PDF, CSV, and JSON behavior. If declined, record acceptance of
   the remaining provider-integration uncertainty.
3. Approve the annotated tag, GitHub Release, and repository visibility change.
4. After the repository becomes public, verify anonymous clone, README,
   license, source archive, issue forms, and private vulnerability reporting.
   Enable secret scanning, push protection, code scanning, and private
   vulnerability reporting where the account supports them.
5. Reconfirm that the protected `main` commit, annotated tag, successful CI
   workflow, release target, and inspected source archives are identical.

## Known limitations

- Keyword Pro is a local single-user application. It has no hosted account or
  authentication layer and must not be exposed directly to a LAN or the
  internet.
- Missing Redis falls back to an in-process idempotency cache. That is suitable
  for one local process, not a multi-instance deployment.
- Live provider coverage, availability, price, and response shape remain
  external dependencies. Offline evidence cannot prove a future paid response.
- The package manager emitted Node's legacy `url.parse()` deprecation warning
  during install and audit. The audit reported no vulnerability, and the
  warning did not originate from the application runtime.

## Publication decision

- Source-tree decision: **pass with owner gates**.
- Existing-private-remote decision: **hold, do not toggle public in place**.
- Paid end-to-end provider decision: **not run, owner approval required**.
